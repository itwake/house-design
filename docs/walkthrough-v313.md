# V3.1.3 · 第一人称漫游

2026-09-10。保留唯一原木方案、全部已确认布局、源几何、Blender/GLB文件和15张同源渲染；增加网页实时行走。不是新的装修方案，也不是照片全景或VR头显模式。

## 使用

模型加载后，点击画面左上方「第一人称漫游」。也可先选房间，再点「步行进入…」。全屋入口从玄关附近开始；每个房间使用碰撞验证后的落脚点，不直接复用可能在墙边的旧展示相机。

| 设备 | 操作 |
|---|---|
| 电脑 | WASD／方向键移动，拖动画面转头，Q/E原地左右转，Shift慢行 |
| 手机／平板 | 按住左下方方向键移动，另一根手指拖动画面转头；可同时操作 |
| 返回 | 右上「退出漫游」，或键盘Esc；恢复所选空间的俯瞰视角 |

漫游期间收起说明卡、剖切／尺寸等操作，保留房间导航和退出按钮。退出后恢复说明卡原来的隐藏偏好与墙体剖切状态，不覆盖已保存的偏好。选择其他房间或切换平面／效果图会退出漫游。

打开弹窗／下载菜单、切到其他应用或页面不可见时停止输入；再次操作需要重新按下按键，不允许按住键的自动连发重新启动。页面离开时恢复俯瞰，避免浏览器缓存返回后保留错误相机状态。

## 范围和限制

- 模拟眼高固定1.60m，没有跳跃、飞行、攀爬和头部晃动；默认1.1m/s，Shift为0.45m/s。长帧时间限制50ms，移动拆为不超过2cm的小步，防止跳过薄墙或玻璃。
- 虚拟身体半径25cm用于操作避障，**不代表真实人体、门扇净开、施工净空或无障碍通行认证**。5cm格网验证的是这套简化虚拟模型，不能推导实际装修已可落地。
- 墙与门洞从既有厘米坐标读取，映射到Three.js的X/Z米。只放行七处内部门洞；六处窗、三个飘窗和入户外侧不可走出。主卫经主卧进入，书房南墙连续，厨房与阳台的共墙不虚构通道。
- 柜体和主要家具用保守平面包围盒阻挡，飘窗桌面和椅子同样阻挡。淋浴只阻挡固定玻璃／立柱，不把整个淋浴盘当墙。附加落地灯在建模脚本内单独定义，碰撞补充其440mm灯罩投影，并用实际GLB包围盒验证坐标一致。
- 为演示通行，临时隐藏七套内部门的19件门片、把手、玻璃和中梃；保留门框与入户门，退出时恢复原可见性。**没有模拟真实开门动作或验证全幅开启**。玻璃门约38mm低门槛和淋浴低台按可跨越展示，没有真实高差步态模拟。
- 原GLB地面止于房间净边界。漫游时仅在既有七个内部门洞的墙厚范围增加薄地面填片，防止移开门片后露空缝；退出隐藏。未改原始GLB、平面图、洞口或下载文件，不增加虚构房间。
- 阳台门继续是待结构核验的条件设计。现实房屋的梁柱、立管、窗台及家具尺寸仍需现场复尺。视觉为现有模型实时渲染，不承诺照片级材质、照明或真实采光。

## 验证

`node tools/test_walkthrough.mjs` 离线执行实际模块和查看器函数：

1. 十个进入点及备用点均不在障碍内；实际`canStand + advanceWalk`在5cm格网中连接8311个位置，全部八个物理房间从玄关可达。餐厅与全屋是公共区的额外导航入口。
2. 墙、窗、家具、落地灯、薄玻璃阻挡；主卫门、书房南墙、双卫边界、厨房—阳台共墙以及不可跨出的飘窗边界。
3. 对角速度、滑墙、小步碰撞、长帧限幅、Shift慢行、双指分别转头／移动、对向按键抵消后的唤醒、暂停后连发抑制、组合键、失焦与监听解绑。
4. 真实查看器的初始化、进入、退出、相机投影、40组房间／剖切／说明卡状态恢复，漫游不调用OrbitControls更新；切换平面、重新聚焦和离页恢复。
5. 实际GLB门构件名与语义分类，通过Three.js网格夹具验证门不被静态合批、可独立隐藏／恢复。仅门材质和构件分类采用夹具，不将它称为WebGL渲染测试。另读取实际灯罩的顶点范围和节点变换验证附加碰撞。

并保留单方案入口、平面/立面、几何与资产校验；单方案回归将169个源模型及渲染资产与V3.1.1逐一比较，确保没有倒退。上线后以HTTP逐一校验27个有效网页资源的SHA。

本轮没有进行浏览器视觉／WebGL交互测试，也没有手机真机测试。桌面和触控的事件、状态与几何验证属于离线回归；设备上的真实手感和性能仍可能有差异。
