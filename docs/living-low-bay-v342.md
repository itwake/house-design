# V3.4.2 · 客厅低飘窗与分片软垫

业主在V3.4.1撤掉桌椅后明确同意“暂时估算一个数字先做低飘窗方案，铺垫”。本次将四个活动方案同步为同一低飘窗构造，卧室飘窗和其他布局均不改。

## 暂估尺寸

| 项目 | 本轮建模值 | 状态 |
| --- | --- | --- |
| 完成地面至原台饰面 | 400mm | 业主授权暂估，未测量 |
| 可拆洗软垫厚度 | 50mm | 设计值，待选材试坐 |
| 完成坐面 | 约450mm | 台高＋软垫，不是现场事实 |
| 两片坐垫 | 每片960×550mm，中缝20mm | 不外伸进客厅 |
| 窗宽、外凸包络 | 沿用2000、600mm | 旧模型占位，仍须复尺 |
| 窗顶 | 沿用2300mm | 未测量；窗框分格也是示意 |

保留白色台体与石材饰面的表达，取消前版高位附加薄木台，软垫直接铺在低台上。两片分开可取下晾晒、拆洗，沿用各方案既有浅米灰亚麻材质。没有新增书桌、椅子、台下抽屉、落地大地台或靠玻璃受力的靠背。

## 不可误读的条件

- 从旧模型900mm占位变成400mm，不表示现场允许切低500mm。现状窗台的实际高度、构造及承载未核实，不能照本图拆台。
- 本次仅修改客厅西窗下墙的模型高度、相应窗框/玻璃/台板和两片软垫；窗顶、窗的平面位置、轮廓、其他墙和门窗、衣柜、厨房与阳台不变。
- 高层窗边不应当作儿童攀玩区域。先核查防坠、开窗限位、无绳窗帘；软垫不是防护，纱窗不是防坠。
- 排查窗角渗水与返潮；不遮挡排水、窗扇和把手，不预设台下可挖空做储物。
- 渲染是设计照明，不代表真实日照、开窗安全或已批准的外立面改造。

## 同步与检查

1. `node tools/update_low_living_bays.mjs` 更新四套源数据和目录；如运行历史布局生成器，应先运行V3.4.1移除桌椅脚本再运行本脚本。
2. 打开V3.4.1各套Blender，通过 `tools/refresh_low_living_bays.py -- --scheme <id> --render bay-living,overall,living,dining --engine CYCLES --resolution 960 --samples <8或12>` 精确重建目标构件。不能在已经修改的场景重复运行该补丁。
3. 如只同步文字说明，使用 `tools/render_low_living_bays.py` 从已生成低台的Blender场景读取，不重新改几何；刷新清单并真实渲染，记录新的渲染时源文件哈希，不修改旧帧来冒充新输出。随后 `node tools/complete_living_bay_renders.mjs` 保留未改空间的原图字节、相机和真实历史来源。客厅相关四视角全部重渲，其余沿用图在网页明确标注“沿用历史模型图 · 本轮未重渲”，不承诺重新计算间接照明。
4. `node tools/test_living_bay_clearance.mjs` 核对400＋50mm与坐垫平面包络；`python -B -X utf8 tools/validate_living_bay_models.py` 逐物体解码实际GLB，核对400mm窗下墙、450mm坐垫顶及其他网格不变。
5. 继续检查四套平面、第一人称通行、手机/窄屏/桌面和实际效果图来源。

质量要求：目录中 `renderSpec.samples` 是各方案最低采样数（方案1/2/3为8，方案4为12）；允许更高采样，不允许降级。每张图记录实际采样数、图像哈希、渲染时源文件、保存场景和相机信息。补丁与重渲脚本从目录读取下限，避免手工把两套方案的采样数填反。

设计思路沿用[100室内设计的窗边卧榻案例](https://www.100.com.tw/article/1414)；安全参考[IKEA窗边儿童安全指引](https://www.ikea.com.tw/zh/safety-at-home/child/play)。这些资料不是本户尺寸和结构依据。
