# V3.2.3 · 厨房与家政阳台共墙大窗

本轮仅修正暖白套间方案。业主确认这段共墙应有大窗；不是在客厅墙上开窗，也没有把阳台当作无外墙的露台。

## 同源尺寸（模型假设，非实测）

- 共墙中心线：X=6810～8350、Y=11210mm，墙厚沿用120mm。
- 窗洞：X=6980～8180mm，宽1200mm；窗台1000mm，洞高1300mm。
- 阳台内侧共墙净宽约1420mm，两端各留约110mm的内侧实墙范围。
- 双轨双扇推拉窗仅为暂定窗型；模型当前展示关闭状态，不新增漫游通道。
- 窗框、两条轨道上错位的窗扇、两片玻璃、把手、石材窗台均是实际网格。
- 厨房北侧原1300mm层板改为920mm，实际范围X=6000～6920mm，距窗洞西端60mm；避免横穿窗口。

窗洞尺度需现场复尺，确认窗套、转角收口、设备及柜体位置。若现状已经有窗，应记录真实洞口；若涉及扩大洞口，应先确认墙体结构和物业条件。本模型不是拆改许可或施工图。阳台外侧围护、外窗、实际采光与通风条件未据此推定。

## 保留内容

所有房间多边形、墙体中心线、门位、飘窗、衣柜、浅台、书房沙发和通长桌、玄关餐柜及暖白材质不变。厨房原水槽、台面、电器和阳台台下柜不变；仅让开挡窗层板。厨房1700mm三轨门、客厅至阳台门不变。原wood方案的模型、渲染与源数据保留作历史对照，未套用本次修正。

## 验证方法

- `test_kitchen_balcony_window.mjs`：对比V3.2.2真实Git快照，检查只新增一个窗洞，确认窗洞两侧分别是阳台与厨房；窗口不成为可穿行门洞。
- `test_suite_plan.mjs`：执行网站实际SVG绘图代码，核对窗洞端点，不另画一张“正确示意图”代替。
- `validate_suite_model.py`：解码GLB实际网格顶点，验证60段墙体实体、真实开洞、两片玻璃及分轨；原厨房网格仅允许层板变化并单独核验其跨度。
- `validate_design_schemes.py`：效果图对应当前源数据和Blender场景的SHA，不沿用旧图并改标签。
- `qa_suite_ui.mjs`：桌面、390px及320px页面回归；两方案窗洞隔离、3D、平面、效果图及漫游。
- `verify_published.mjs`：上线后核对远端实际文件与本地SHA。

厨房和阳台效果图从共墙两侧取景；全套16张图从同一版Blender场景输出。所有尺寸及实际居住适用性仍需现场复核。
