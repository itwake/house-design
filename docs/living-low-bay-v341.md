# V3.4.1 · 四方案客厅窗前留白

## 已落实的改动

四个活动方案（wood / suite / family / laundry）统一取消客厅西飘窗前的2000×650mm桌面、全部支架和桌面用品，以及两把椅子。窗体、台体、原薄饰面、其他家具、墙和门均不改。二维、实际GLB、Blender及对应效果图一起更新；历史归档仍保留旧版本。

**照片是定性证据，不是尺子。** 用户2026-09-26实拍显示窗台较低，但没有可靠的尺寸标定。模型原900mm台高明显不能作为现状依据，本次明确标为旧占位，不擅自猜一个新高度。也没有擅加软垫、抬高平台或新柜子。

## 更适合本户的下一步

1. **首选：原台保留＋活动薄垫。** 先排查窗框、窗角渗水和石材边缘；实测、试坐后考虑约30–50mm可拆洗坐垫及少量靠垫。暖灰米色织物更容易延续现有暖白浅木风格。垫子可分段取下晾晒，不封死窗框排水和检修。
2. **只做成人短时休憩，不急于变成第二张沙发。** 台面过窄时，保留硬质窗台比外扩大地台更适合客厅；很低的原台也不一定值得加厚到标准坐高。可先用临时垫试坐、起身，再决定。
3. **收纳不要默认从台下“挖”出来。** 照片的白色面板不能证明后面是空腔；可能是饰面、原柜或结构覆盖。未核实前，不承诺拆台、抽屉或隐藏柜。方案4已有东侧书架，窗前可继续留空。
4. **儿童防坠优先。** 28楼、家有小孩，低台本身也容易成为攀爬面。先由专业人员确认窗体、防护、开窗限位及无绳窗帘；纱窗不是防坠设施，靠垫不能依靠玻璃受力。安全条件不明时，先保持留白，不布置儿童阅读/攀玩角。

## 量这四项再深化

- 完成地面到台面上表面的高度（不要用毛坯地面量）。
- 台面可用净深、有效总长，以及两端窗垛位置。
- 从台面起算的实际防护条件与窗扇开合范围；靠垫不能挡把手。
- 台下是否原柜/实心结构，窗框是否渗水、有无需要检修的位置。

网文常见窗边坐位约400–500mm高，只能作为试坐参考，不是必须把原台改到这一尺寸的理由。

## 复现

历史布局生成脚本后执行 `node tools/update_living_bays.mjs`，再用各方案原构建脚本建模；或打开现有方案的Blender文件运行 `tools/refresh_living_bays.py -- --scheme <id> --render overall,living,dining,bay-living --engine CYCLES --resolution 960 --samples <8或12>`，只删除五组已标记构件，保留其他实际网格、灯光和相机。两种路径都读取同一份更新后的源数据。

全屋、客厅、餐区及客厅飘窗四个相关视角必须重新渲染。未改房间或画面不含该桌椅的其余视角可保留已核对的原图：运行 `node tools/complete_living_bay_renders.mjs`，检查原图字节确实来自已发布Git版本，并保留旧场景/源数据/相机哈希，额外标记 `retainedFrom`；不把旧哈希改成当前哈希。网页会显示“沿用上版模型图 · 本轮未重渲”，这类图没有重新计算间接照明。若需要整套全部重新计算光照，可用 `--render all`。

`node tools/test_living_bay_clearance.mjs` 验证源数据只删除指定构件；`python -B -X utf8 tools/validate_living_bay_models.py` 从Git读取旧GLB并逐物体比较实际三角形、材质、坐标和附属数据。其他现有布局、漫游与页面测试继续执行。

本次实际模型验证：四方案各删除61个桌、支架、椅和附件网格；其余分别1350、1439、1376、1654个网格与已发布V3.4.0逐物体一致。共27张当前模型重渲图（包含四方案全部客厅相关视角）、39张明确标记来源的未改空间参考图；没有用旧图冒充新渲染。
